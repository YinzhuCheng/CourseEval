# 目标作业系统：LLM 辅助评分 — 规格说明（六章）

本文档面向**仅有教师与学生角色**的目标作业系统，描述如何在其上增加：嵌套 zip 附件处理、文本/图片/多模态三路归一、拼接为单一输入后调用外部 LLM、异步评分任务、多次提交取最高分、课程级 LLM 配置与配额等。**不绑定**编程语言、框架或消息队列具体产品。阅读本文档**不需要**访问任何其他代码仓库。

---

## 第 1 章　范围、角色与页面

### 1.1 范围

- **纳入**：作业链路中的发布、学生提交、评分、提交与评分历史、附件存储与处理、异步自动评分、课程级 LLM 相关设置、配额与安全。
- **不纳入**：论坛等非作业模块。

### 1.2 角色

- **教师**：本课程内**作业与 LLM 相关设置的责任人**——发布与编辑作业、配置是否启用自动评分及本课程 LLM 参数（在系统策略允许内）、查看学生附件与下载、查看评分任务状态、填写或修改**评分**（数值与评语，界面上不区分来源）。
- **学生**：在规则允许下上传附件、查看自己的成绩与评语、查看本人提交历史（可选简化展示）。

### 1.3 与现有页面对齐（信息架构级）

以下仅描述**信息与入口**，不写具体控件实现。

| 页面/区域 | 应补充的信息与入口 |
|-----------|-------------------|
| **作业列表** | 作业标题、课程、截止时间、发布信息；可增加简短说明：是否启用自动评分、评分规则提示（如多次提交取最高分）。 |
| **作业详情** | 作业正文、教师说明附件、截止时间；同上评分规则提示。 |
| **学生提交 / 评分表** | 每名学生一行：提交状态、提交时间、附件链接、**评分**（单一列：分数 + 评语/评论入口）；建议增加**自动评分任务状态**（排队中 / 处理中 / 成功 / 失败），避免教师将「排队中」误认为未提交。 |
| **作业编辑（教师）** | 开关「启用 LLM 辅助评分」、满分、与本课程 LLM 配置的关联或作业级覆盖；附件说明文案（允许 zip、单附件槽、建议大小上限等）。 |

## 第 2 章　概念模型与数据（最少必要实体）

### 2.1 核心实体

| 实体 | 说明 |
|------|------|
| **课程** | 组织教师、学生与作业的容器。 |
| **作业** | 隶属于课程；含标题、正文、截止时间、是否启用自动评分等。 |
| **成员** | 学生（及教师）与课程的关联。 |
| **提交记录** | 同一学生对同一作业可有**多条**提交记录（多次提交）；按时间有序。 |
| **附件** | 与单次提交绑定：**每人每作业每次提交一个附件槽**；该槽对应**一个上传文件**，该文件可为普通文档或 **zip**（zip 内可多文件、可含嵌套 zip）。 |
| **异步评分任务** | 表示「对某次提交执行附件处理 + LLM 评分」的工作单元；有独立状态，供页面展示。 |
| **课程级 LLM 配置** | 端点、模型、超时、重试策略、是否启用等；由教师在本课程内维护（在系统允许范围内）。 |

### 2.2 评分在界面上的呈现

- **界面上不区分**分数来自 LLM 还是教师；统一显示为「评分」。
- **内部是否保留**来源、时间戳等元数据：作为**可选实现细节**，用于审计与排错；若保留，默认不向学生展示，教师界面可可选展示。

### 2.3 存储（概念层）

- **原始附件**：必须可持久检索（含 zip 原包），便于复核与重跑任务。
- **解压产物与文件清单**：解压得到的文件宜落在受控存储中，并记录清单（相对路径、大小、可选哈希）；若仅临时解压，须在任务重试时能复现相同的拼接输入。清单用于说明「纳入了哪些文件、哪些被跳过」。

## 第 3 章　提交与成绩规则（含多次提交取最高分）

### 3.1 截止与迟交

- 截止时间、是否允许迟交、迟交是否仍触发自动评分：与目标系统现有规则**对齐**，或做**最小扩展**（例如增加「截止后禁止上传」或「允许上传但不计分」之一），并在部署或作业级配置中**写死一种语义**，避免歧义。

### 3.2 多次提交与对外唯一分数

- 提交记录**按时间有序**。
- 设某学生在该作业下，所有能产生**有效数值分数**（0～满分闭区间）的来源构成集合，**对外展示的一条分数** = 这些数值中的**最大值**。
- **教师手动改分**：接受「教师改高后，界面以较高者为准」——教师给出的分数参与上述 max；若教师后续调高/调低，展示分随规则更新（调低时 max 可能来自历史自动分或更高一次教师分，产品需与 3.3 边界一致）。

### 3.3 边界行为（简短条目）

| 情况 | 建议行为 |
|------|----------|
| 尚无任何有效数值分 | 评分列显示为空或「未评分」（按产品文案）。 |
| 仅自动评分任务失败、从未有分 | 不进入 max；若教师未填分，仍为未评分。 |
| 教师清空评分 | 若实现为「清空作业行分数」，则 max 仅来自各次提交的候选分；若全部失败且无候选分，回到未评分。须在界面或帮助中说明。 |
| 部分提交成功、部分失败 | max 只统计有效分数；失败可在任务列显示原因。 |
| 多次自动分与教师分并存 | 展示分仍为 max，不展示来源标签。 |

### 3.4 实现等价说明（可选）

- 可在「作业行单一分数 + 每次提交候选分」两种实现间择一，只要**对外 max 语义**与上表一致即可（见第 2 章「不区分来源」）。

## 第 4 章　附件与嵌套 zip：解压、安全与「三路合一」输入构造

### 4.1 单文件：三类路径

每个待处理的叶子文件（非 zip 单文件上传，或 zip 解压后的文件）按类型归入以下之一（**互斥**，优先级由实现定义并文档化）：

| 类型 | 包含示例 | 处理 |
|------|----------|------|
| **文本** | 纯文本、Markdown、常见源码、**Office/doc/docx（统一走文本抽取）** | 转为可供模型阅读的 Unicode 文本；超长截断并记录。 |
| **图片** | png、jpeg、gif、webp 等 | 进入图片输入列表，与多模态 API 组合。 |
| **多模态** | **PDF**、**Ipynb** 等 | PDF：将页面渲染为**页图序列**，再与模型做多模态输入；Ipynb：清洗单元格与输出，抽取文本与可选截图/输出图块，再与模型做多模态或长文本输入；最后在拼接层与其它类型统一编排。 |

无法归类或抽取为空：跳过该文件，记入说明列表。

### 4.2 Zip（含嵌套）与解压策略

- **嵌套 zip**：支持递归解压，直至达到**最大嵌套深度**（可配置）或**总展开大小 / 文件数**上限。
- **安全**：防范路径穿越、zip 炸弹、资源耗尽；超限时可「跳过后续条目并尽力评分」或「整单失败」，产品择一并固定。
- **遍历顺序**：对参与拼接的文件使用**稳定、可复现**的顺序（如 UTF-8 路径字典序）。

### 4.3 合并算法（单一 LLM 用户侧材料）

- 将第 4.1 节各文件的处理结果，按约定顺序**粘贴拼接**为**一份**材料，建议：
  - 固定分隔标题（如按路径分段）；
  - 文本块顺序拼接；
  - 图片与 PDF 页图、Ipynb 图块按所选模型 API 要求组织为「一段文本 + 若干图」或「多段图文」；
  - 尾部附截断与跳过说明。
- **总长度 / token 预算**：设硬上限；超出时按**优先级**截断或丢弃（建议：**作业说明与量规 > 学生文本 > 附图**；同档内按路径序丢弃后者）。优先级应可配置。

### 4.4 失败语义

- **解压失败**或**全盘无可喂内容**：该次异步任务标记失败；学生是否允许在规则下**重传**由产品定（是否计为一次新提交同理）。
- **部分文件有效**：对有效部分完成评分，并在评语或系统说明中列出未纳入项。

## 第 5 章　LLM 调用、调度、输出规格与异步队列

本章假定读者**无法查阅任何外部实现**，因此把调度层次、重试与输出格式写为可独立实现的约定。

### 5.1 调用输入（逻辑）

每次针对**一条提交记录**构造一次「评分调用」时，逻辑输入至少包括：

- 作业标题与正文要求；
- 教师可选提供的参考答案、量规或评分要点；
- 第 4 章合并后的**学生材料**（文本块 + 按 API 能力附带的图片列表）；
- **满分**（`max_score`）与允许的评分粒度（如整数或一位小数）；
- **响应语言**等业务参数（若课程配置）；
- 可选：**系统级指令**（例如要求只输出 JSON、不得泄露隐藏测试、对评语风格的要求），与第 5.3 节绑定。

### 5.2 模型响应的**输出规格**（必须可实现、可校验）

目标系统必须规定一种**机器可解析**的评分结果格式，否则无法自动写库与参与 max 比较。推荐以下约定（实现可采用等价变体，但须在部署文档中写死字段名与规则）。

#### 5.2.1 载体形式

- 模型**只返回一段文本**，且该文本在去掉首尾空白后，应能解析为 **JSON 对象**（单一根对象，不要数组作根）。
- 若模型用 Markdown 代码块包裹 JSON（例如 \`\`\`json … \`\`\`），实现须在解析前**去掉围栏**，只保留内部 JSON 文本。
- 若模型在 JSON 前后夹杂解释性文字，实现应**优先**尝试：从全文提取**第一个**完整的 `{ … }` 对象并解析；若失败则整段解析失败，进入第 5.4 节「可重试」路径。

#### 5.2.2 必填字段（语义名，实现可映射为具体键名）

实现须选定两个键名并在全系统一致，下文用语义描述：

| 语义 | 要求 |
|------|------|
| **建议分数** | 数值类型（整数或小数），必须在 **0 与当前作业满分（含）** 之间。超出范围、缺失、或非数值 → **校验失败**。 |
| **评语** | 字符串；允许为空字符串；不得为 `null` 若系统选择「必填键存在」——若允许 `null` 则须在解析时规范化为 `""`。 |

示例形状（键名仅为说明，可替换）：

```json
{
  "score_suggestion": 87.5,
  "comment_text": "……"
}
```

#### 5.2.3 校验失败时的语义

- **JSON 语法错误**（无法 `parse`）、**根类型不是 object**、**缺必填键**、**分数不可解析或越界** → 一律视为**当次模型输出不可用**。
- 此类失败在**同一 API 端点**上通常可按「瞬时模型胡输出」处理，纳入第 5.4 节**同一端点内重试**；若连续多次仍失败，再进入第 5.3 节下一端点。

#### 5.2.4 成功后的内部使用

- 将**建议分数**写入该次提交对应的候选分（参与第 3 章 max）；将**评语**写入可展示或可合并的评语字段（与教师评语合并策略由产品定）。

### 5.3 端点组与两层调度（调度 / 故障转移）

为避免单点不可用，配置中采用 **「端点组」**：一组**有序**的 API 调用目标（下文称 **#1、#2、#3…**）。每个目标包含：基址 URL、鉴权方式、模型名、超时、以及**仅作用于该目标**的重试参数（见 5.4）。

**外层调度（端点间故障转移）**：

1. 从 **#1** 开始，尝试完成「一次完整评分调用」（含 5.4 节内层重试）。
2. 若 **#1** 在耗尽内层重试后仍失败，记录原因，再对 **#2** 重复；依此类推。
3. 若所有端点均失败，该异步任务进入**终态失败**，并保存**最后一条错误摘要**供教师查看。

**与「连通性测试」的关系（可选但强烈建议）**：

- 每个端点可维护「最近一次连通/鉴权测试结果」。若某端点已知**长期不可用**（如密钥吊销），可直接跳过以节省时间；具体策略由实现定义，但不得静默吞掉可恢复错误。

### 5.4 内层重试（同一端点上的「重新请求」）

在**同一个端点**上，网络抖动、限流、偶发 5xx、或 5.2 节所述「输出无法校验」均可能发生。内层重试约定：

| 项目 | 说明 |
|------|------|
| **可重试的典型情况** | 请求超时；HTTP 5xx；显式限流（429 等）；连接重置；**JSON 解析或评分字段校验失败**（视为模型偶发未遵守格式）。 |
| **不宜重试的典型情况** | 鉴权失败（401/403 且确认为密钥错误）；请求体过大被拒（413）且无法通过截断解决；内容安全策略明确拒绝且换提示仍无效（实现可将此类记为终态并提示教师）。 |
| **次数与退避** | 对可重试错误：最大尝试次数 `N`（建议 ≥2）、首次等待 `T0` 秒，之后按**指数退避**（例如第 k 次等待 `T0 × 2^(k-1)`），并设**上限**（例如单次等待不超过 120 秒），避免任务永久悬挂。 |
| **幂等与计费** | 同一任务内多次重试应对**同一逻辑调用**；**仅在成功拿到合法 JSON 并校验通过后**才记一次「成功计费」与 token 消耗（见第 6 章），避免重复计费。 |

**与外层关系**：内层在**当前端点**上穷尽后，才切换到下一端点；**不在**端点之间做指数退避混用（避免语义混乱），但可对「整组失败」单独定义冷却（可选）。

### 5.5 超时

- 每次对上游 HTTP/SDK 的调用须设**连接 + 读超时**（可合并为单一超时配置），超时记为可重试（除非已达内层上限），避免工作者永久阻塞。

### 5.6 异步队列的含义（不写具体产品名）

| 要点 | 说明 |
|------|------|
| **为何需要** | 解压、格式转换、多模态与 LLM 调用耗时长、易失败，不宜阻塞用户 HTTP 请求全程。 |
| **一条工作任务** | 对应「对**某一次提交记录**执行：第 4 章输入构造 → 第 5.3～5.4 节 LLM 调用 → 写回候选分与任务状态」的完整管线。 |
| **页面可见状态** | 排队中、处理中、成功、失败（可细化为可重试/终态）；不暴露底层中间件名称。 |
| **实现自由度** | 不假设 Redis、Kafka、数据库轮询等；任何能满足异步、可重试、可多工作者扩展的机制均可。 |
| **并发** | 可配置「每课程 / 每部署同时进行的任务数」，防止拖垮上游 API 或本地 CPU（解压与 PDF 渲染）。 |

### 5.7 与提交的关系

- 新提交若启用自动评分，应**入队**新任务；成功后参与第 3 章 max 更新。
- **重评**：对历史提交再次触发时，应新建任务（或同一任务号重置状态，二选一但须防重复计费），更新该次候选分，再参与 max。

## 第 6 章　Token 配额、安全、验收

### 6.1 Token 配额（计量维度、预检、记账与超额）

本节给出**可独立实现**的配额语义；具体表结构由实现决定。

#### 6.1.1 计量对象

- **输入 token**、**输出 token** 及（若上游返回）**合计 token**；若某供应商只返回合计，则只记合计。
- **归属**：建议至少支持以下维度之一或组合（部署时写死）：
  - **按学生用户 + 自然日**（见 6.1.4 时区）；
  - **按课程 + 自然日**（防止单课刷爆）；
  - 可选：**全平台每日上限**（运维硬顶）。

#### 6.1.2 「日」的边界

- 必须固定一种 **「计费日」** 的时区（例如东八区自然日或 UTC 自然日），并在配置中写明；所有「每日额度重置」均按此时区。

#### 6.1.3 调用前预检（粗算）

在真正发起 HTTP 请求前，用**启发式**估算本次调用可能消耗的 token，例如：

- 文本：按字符数除以经验系数（如每 4 字符≈1 token，需可配置）并加固定开销；
- 图片：按张数与分辨率/字节数估算视觉 token（若模型文档有公式则优先遵循文档）；
- 再加上**预计最大输出 token**（受 `max_tokens` 或等价参数约束）。

若 **估算值 + 已用额度 > 限额**：

- **策略 A**：任务直接失败，提示「今日额度已用尽」；
- **策略 B**：任务保持排队，延迟到次日重置后再试（需持久化队列与可解释的「等待额度」状态）。

须在产品中选一种并写清用户可见文案。

#### 6.1.4 调用后记账（精算）

- 若 HTTP 调用**成功**且响应体中包含用量字段（不同供应商字段名不同），解析 **prompt / completion / total** 中至少一项，并**累计**到对应学生与（若启用）课程、日的计数器。
- 若响应**无**用量字段：可用「估算值」记一次**近似**，或记为 0 并打日志告警——须在运维文档中说明偏差风险。
- **重试**：同一逻辑任务内多次失败重试**不应**重复累计；仅在**一次被认定为成功**的响应上记账。

#### 6.1.5 超额与降级

- 当预检或运维策略判定不可调用时，任务应**明确失败原因码**（如 `quota_exceeded`），供界面展示；教师侧可配置是否允许「仅手工评分」绕过自动任务。

### 6.2 安全与合规

- **密钥**：仅存服务端，按课程或部署隔离，不下发浏览器；轮换时旧任务应失败并提示更新配置。
- **课程隔离**：一课程的配置与数据不应被其他课程访问。
- **数据出网**：作业内容发往外部模型服务须有**可配置告知**（协议或课程说明）。
- **附件与解压**：重申第 4.2 节；日志避免打印密钥与全文作业。

### 6.3 验收清单

- 单文件、zip、**嵌套 zip** 在限额内能完成拼接并评分；超限行为符合第 4 章。
- Office/doc **文本**路径；PDF、Ipynb **多模态**路径；纯文本与图片路径行为正确。
- **合并为一份输入**再调模型（若采用分块摘要再合并，须单独成文说明算法）。
- **多次提交取最高分**与第 3.3 节边界一致。
- **输出 JSON** 符合第 5.2 节；非法输出触发第 5.4 节重试路径。
- **端点组外层 + 单端点内层重试**符合第 5.3～5.4 节。
- **Token**：预检、成功调用后记账、按日重置与超额行为符合第 6.1 节。
- 异步状态可观测；终态失败原因可读。
